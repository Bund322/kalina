# Калина — сайт тату- и пирсинг-студии

Статический сайт на [Astro](https://astro.build): главная, страницы мастеров, 3D-голова с проколами (`/piercing`)
и 3D-манекен с картой боли (`/tattoo`). Весь контент лежит в JSON-файлах и папках с фото — правится без
программирования.

## Как запустить у себя

Нужен [Node.js](https://nodejs.org) 22 или новее.

```bash
npm install
npm run dev
```

Сайт откроется на http://localhost:4321 и будет обновляться при каждой правке файлов.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | локальный сервер для разработки |
| `npm run build` | собрать сайт в папку `dist/` — её и заливают на хостинг |
| `npm run preview` | посмотреть собранный `dist/` |
| `npm run check-links` | проверить внутренние ссылки в собранном `dist/` |
| `npm run placeholders` | создать фото-заглушки для файлов из JSON, которых ещё нет |
| `npm run models` | пересобрать 3D-модели из `assets-src/` (нужно редко) |

## Как поменять контент

После любой правки сайт нужно пересобрать и выложить — при работе через GitHub это происходит само
(см. «Деплой»). Если в JSON ошибка или нет нужного фото, сборка остановится и напишет, что не так.

### Мастера

Файл `src/data/masters.json`, по записи на мастера:

```json
{
  "slug": "alina",
  "name": "Алина",
  "photo": "photo.jpg",
  "direction": "tattoo",
  "styles": ["ботаника", "fine line"],
  "about": ["Первый абзац.", "Второй абзац."],
  "telegram": "https://t.me/…",
  "instagram": "",
  "works": [
    { "photo": "work-1.jpg", "caption": "Ботаника, предплечье" },
    { "photo": "work-2.jpg" }
  ]
}
```

- `slug` — адрес страницы (`/masters/alina`), латиницей, без пробелов.
- `direction` — `tattoo`, `piercing` или `both`.
- `telegram`, `instagram` — необязательны; если пусто, на странице мастера кнопка «Записаться» студии.
- `works` — до 9 работ. `caption` (подпись) необязательна. Первая работа — обложка мастера в галерее на главной.
- Фото лежат в `src/content/masters/<slug>/` с теми же именами, что в JSON.

**Добавить мастера:** допишите запись в `masters.json`, создайте папку `src/content/masters/<slug>/` и положите
туда фото. **Удалить:** уберите запись и папку.

### Фото

Чтобы заменить фото-заглушку, положите своё фото **с тем же именем файла** поверх старого. Формат — JPG, PNG
или WebP; при сборке фото само сжимается и уменьшается, но лучше не больше 2–3 МБ на снимок.

- мастера и их работы — `src/content/masters/<slug>/`;
- проколы — `src/content/piercings/` (имена вида `helix-1.jpg`, список — в `piercings.json`).

### Проколы

`src/data/piercings.json`: у каждого прокола `name`, `description`, `price` (строкой, как на сайте:
«от 3 500 ₽»), `healing` и `photos` (1–3 файла). Поля `points` — координаты точки на 3D-модели, их не трогайте.

### Зоны тату

`src/data/tattoo-zones.json`: у каждой зоны `name`, `pain` (боль от 1 до 5), `why` (почему так) и `tip` (совет).
`id` зон не меняйте — по ним сайт находит участок на модели.

### Прайс и контакты

`src/data/studio.json`: адрес, часы, телефон, ссылки на Telegram и WhatsApp, список цен. У цены `category` —
`tattoo`, `piercing` или `common` (общие позиции): по ней прайс делится между страницами тату и пирсинга.

## Деплой

### Превью на GitHub Pages (на время разработки)

Каждый push в ветку `dev_seits` собирает сайт и выкладывает его на https://bund322.github.io/kalina/
(`.github/workflows/pages.yml`).

Включить один раз: в репозитории на GitHub **Settings → Pages → Build and deployment → Source:
GitHub Actions**. Если деплой падает с ошибкой про защиту окружения, откройте **Settings → Environments →
github-pages** и разрешите в «Deployment branches» ветку `dev_seits`.

Когда сайт переедет на хостинг, файл `.github/workflows/pages.yml` можно удалить.

### Свой хостинг (Timeweb / SprintHost)

Сайт статический: на хостинг заливается только содержимое папки `dist/`, PHP и базы данных не нужны.

**Автоматически через GitHub Actions** (`.github/workflows/deploy-hosting.yml`):

1. В панели хостинга создайте FTP-доступ к папке сайта (обычно `public_html` или `www/<домен>`).
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**, заведите:

   | Секрет | Что вписать |
   | --- | --- |
   | `FTP_SERVER` | адрес FTP-сервера из панели хостинга |
   | `FTP_USERNAME` | логин FTP |
   | `FTP_PASSWORD` | пароль FTP |
   | `FTP_SERVER_DIR` | папка сайта на сервере с `/` в конце, например `public_html/` |
   | `FTP_PROTOCOL` | необязательно: `ftps` (по умолчанию) или `ftp`, если хостинг не умеет FTPS |

3. Запустите вручную: **Actions → «Деплой на хостинг» → Run workflow**.
4. Чтобы сайт обновлялся сам при каждом push в `main`, раскомментируйте в workflow блок `push`.

**Вручную:** `npm run build` и залейте содержимое `dist/` в папку сайта через FTP-клиент (например, FileZilla)
или файловый менеджер в панели хостинга.
